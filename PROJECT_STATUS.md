# Статус проекта: Калькулятор билетов TETYS BLUE (Сезон 2026)

Этот файл содержит историю последних изменений и план дальнейших работ по проекту. Он поможет быстро сориентироваться при переносе проекта на другой ПК.

## ✅ Что уже сделано (Последние изменения)

### 1. Архитектура и UI (Интерфейс)
* **Двухколоночный дизайн (Dashboard):** Интерфейс разделен на левую колонку ("Параметры посещения") и правую ("Список посетителей"). Это решило проблему мобильной версии, где меню было слишком сжатым.
* **Вкладка "Быстрый расчет":** Добавлена вкладка для моментального расчета стоимости без ввода ФИО и дат рождения гостей (ADL, CHLD, PENS, INF).
* **Модальные окна:** Реализовано чистое модальное окно поверх экрана для установки индивидуальных цен.

### 2. Бизнес-логика и Расчеты
* **Ручная корректировка цен:** Возле стоимости билета для каждого гостя добавлена иконка "Карандаш" (✏️). При клике открывается окно, позволяющее менеджеру установить индивидуальную цену, которая пойдет в итоговый чек.
* **Раннее бронирование (Скидка 15%):**
  * Добавлен переключатель (тумблер), который появляется при выборе дат визита с 1 по 23 августа.
  * Убрана жесткая привязка к часам, чтобы избежать багов из-за неправильных часовых поясов на устройствах менеджеров.
  * Исправлен баг "залипания" нерабочей акции путем обновления Service Worker.
* **Расчет прибыли (Маржинальность):** В объект тарифов `CONFIG.tariffs` внедрен параметр `net` (себестоимость). Система теперь корректно учитывает разницу между ценой продажи (Турист/Агент) и себестоимостью для расчета чистой прибыли.

### 3. Техническая часть
* **Обновление Service Worker (sw.js):** 
  * Версия кэша повышена до `tetys-calc-v4`. 
  * Добавлены команды `self.skipWaiting()` и `self.clients.claim()`, чтобы браузеры менеджеров мгновенно применяли новый код при обновлении страницы, не требуя закрытия всех вкладок (Решило проблему "акция не сработает").
* **Автосохранение черновика:** Приложение автоматически сохраняет введенных туристов, выбранный тариф и тип клиента в `localStorage` (ключ `tetisBluDraft`). При случайном обновлении страницы данные не теряются.


## 🚀 Что планируется сделать дальше (План работ)

### 1. Масштабный рефакторинг кода (Разделение на модули)
* **Проблема:** Файл `app.js` стал слишком большим (более 3400 строк). Это усложняет поддержку и внесение новых функций.
* **Решение:** Планируется разбить `app.js` на несколько логических модулей, например:
  * `config.js` (тарифы, настройки, конфигурация)
  * `pricing.js` (формулы расчета скидок, себестоимости и итоговых цен)
  * `ui.js` (отрисовка DOM, обработчики кнопок, модальные окна)
  * `storage.js` (работа с localStorage, черновиками)
* **Code Review (Проверка кода):** После или во время рефакторинга провести строгий аудит всего кода. Удалить дублирования, неиспользуемые переменные, улучшить наименования функций и привести проект к единому стандарту (чтобы избежать «говнокода» и сделать код легко читаемым для любого разработчика).
* **Риски:** Необходимо провести рефакторинг аккуратно, шаг за шагом, чтобы не сломать текущий стабильный функционал.

### 2. Улучшение работы в Офлайн-режиме (PWA)
* Убедиться, что разбитый на модули код корректно кэшируется в `sw.js`.
* Реализовать уведомления для менеджеров о том, что "Приложение обновлено до новой версии".

### 3. Дальнейшее развитие функционала
* Интеграция с базой данных (Supabase) для централизованного хранения чеков, если потребуется синхронизация между менеджерами.
* Расширение аналитики (сбор статистики по типам скидок и самым популярным тарифам).
